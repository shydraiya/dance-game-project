# Dance Game

웹캠으로 사용자의 자세를 인식하고, 음악에 맞춰 제시되는 동작을 따라 하는 Unity 기반 댄스 게임입니다. 기준 동작과 실제 자세를 비교해 점수와 정확도를 기록합니다.

## 프로그램 실행

### Windows 실행 파일로 플레이

1. 전달받은 빌드 폴더를 통째로 압축 해제합니다. `.exe`만 따로 옮기지 마세요. 같은 폴더의 `UnityPlayer.dll`, `*_Data`, `MonoBleedingEdge` 등도 필요합니다.
2. 웹캠을 연결하고 Windows에서 데스크톱 앱의 카메라 사용을 허용합니다. 노트북 내장 웹캠도 사용할 수 있습니다.
3. 빌드 폴더의 게임 `.exe`를 실행합니다. Unity Editor는 필요하지 않습니다.
4. 곡 선택 화면에서 `↑` / `↓`로 곡을 고르고 `Enter` 또는 `Space`로 시작합니다.
5. 카메라에 전신이 보이도록 서서, 준비 안내 후 양팔을 옆으로 펼친 **T포즈**를 유지합니다. 인식과 카운트다운이 끝나면 게임이 시작됩니다.
6. 음악과 화면의 기준 동작을 따라 합니다. 결과 화면에서는 아무 키나 눌러 곡 선택으로 돌아갑니다.

시작 화면은 **1920×1080 창 모드**이며, 해상도는 고정입니다. 조명이 밝고 팔·다리가 화면 밖으로 잘리지 않는 환경에서 사용하세요.

### 소스 코드로 실행·빌드

1. 저장소를 내려받고 Unity Hub에서 프로젝트 루트 폴더를 추가합니다.
2. **Unity 6000.4.0f1**로 엽니다. Windows 빌드에는 해당 플랫폼 빌드 모듈이 필요합니다.
3. 패키지와 에셋 가져오기가 끝나면 `Assets/Scenes/Song Selection.unity`를 열고 Play를 누릅니다.
4. 실행 파일을 만들려면 Build Profiles에서 **Windows / x86_64**를 선택하고, 아래 두 씬을 순서대로 포함해 Build합니다.
   - `Assets/Scenes/Song Selection.unity`
   - `Assets/Scenes/Pattern Test.unity` — 실제 게임 플레이 씬

Windows 빌드는 Direct3D 11을 사용합니다. 빌드 후 `SongFileBuildProcessor`가 `Assets/Patterns`와 `Assets/Musics/wav`를 `*_Data` 아래로 자동 복사합니다. 빌드 결과물의 폴더 구조를 유지해야 음악과 패턴을 읽을 수 있습니다.

명령행 빌드도 지원합니다. 설치 경로와 프로젝트 경로를 환경에 맞게 바꿔 실행하세요.

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.4.0f1\Editor\Unity.exe' `
  -batchmode -quit -projectPath 'C:\Projects\dance-game project' `
  -executeMethod CommandLineBuild.BuildWindows64 `
  -buildOutput 'C:\Builds\DanceGame\DanceGame.exe' `
  -logFile 'C:\Builds\dance-game-build.log'
```

60 / 120 FPS는 **게임 렌더링 목표값**입니다. 카메라 촬영 속도나 자세 추론 속도를 같은 값으로 보장하지 않습니다.

## 듀얼 카메라 모드

정면 웹캠과 측면 카메라로 같은 사람을 촬영하고, 두 영상에서 추정한 자세를 합쳐 정면에서 가려지는 동작의 인식을 보완하는 기능입니다. 측면 카메라는 스마트폰을 DroidCam으로 PC에 연결해 사용할 수 있습니다. 정확도 향상을 위한 기능이며, 실제 개선 정도는 카메라 배치·영상 지연·자세 인식 상태에 따라 달라집니다.

### 연결과 실행

1. 기본 웹캠을 사용자 정면에, 보조 카메라를 측면에 놓습니다. 두 영상 모두 같은 사람의 전신이 들어오도록 배치합니다.
2. 스마트폰을 보조 카메라로 사용하는 경우, DroidCam 연결을 완료하고 PC에서 **장치 이름에 `DroidCam`이 포함된 카메라**로 인식되는지 확인합니다.
3. 두 카메라를 연결한 상태에서 게임을 실행하고 곡을 선택합니다. 플레이 씬에 진입할 때 장치를 확인하며, 보조 영상이 준비되면 별도 모드 선택 없이 병합을 시작합니다.
4. 정면 카메라를 바라보고 T포즈 준비 과정을 진행합니다. 개발용 `D` 키로 카메라 디버그 화면을 확인하거나, `T` 키로 웹캠 단독·병합 자세 비교 결과를 CSV에 기록할 수 있습니다.

### 자동 연결 조건과 제한

- **일반 웹캠 두 대만 연결하면 자동으로 켜지는 방식은 아닙니다.** 현재 코드는 카메라 수가 아닌, 이름에 `DroidCam`이 포함된 장치의 존재 여부로 보조 입력을 활성화합니다. 다른 이름의 스마트폰 웹캠 앱이나 두 번째 USB 웹캠은 현재 자동 병합 대상이 아닙니다.
- 기본 자동 선택에서 정면 입력은 이름에 `DroidCam`이 없는 첫 번째 장치, 보조 입력은 `DroidCam`이 포함된 첫 번째 장치입니다. 실제 설치 위치를 인식해 정면·측면을 구분하지 않으므로, 일반 웹캠이 여러 개라면 선택된 영상을 확인해야 합니다.
- 정면 웹캠 없이 DroidCam만 연결한 구성은 두 개의 독립된 입력을 보장하지 않습니다. 정면용 웹캠과 보조용 DroidCam을 각각 준비하세요.
- 플레이 씬 진입 시 DroidCam이 없으면 웹캠 단독으로 진행합니다. 이후 연결했다면 곡 선택으로 돌아갔다가 다시 시작하세요. 장치는 있지만 영상이 아직 준비되지 않은 경우에는 정면 웹캠을 유지하면서 보조 영상 준비를 기다립니다.

### 자세를 합치는 방식

몸통 방향과 골반 중심을 기준으로 보조 자세를 정면 자세에 맞춘 뒤, 사용할 수 있는 관절을 **정면 90% + 측면 10%** 비율로 합칩니다. 보조 관절의 visibility가 0.5를 초과하고 최근 0.5초 이내의 자세이며 방향 정렬이 가능한 경우에 반영합니다. 이 조건을 충족하지 않는 보조 관절은 제외하고 정면 값을 사용합니다.

병합 결과는 아바타 움직임과 동작 판정에 사용됩니다. 두 입력의 최신 자세를 합치는 구현으로, 카메라 프레임의 정밀 동기화나 다중 시점 삼각측량을 수행하는 방식은 아닙니다. 카메라 두 대의 자세 추론을 실행하므로 단독 모드보다 CPU 부하가 늘어납니다.

## 실행 환경과 사양

**최소·권장 사양은 아직 벤치마크로 확정하지 않았습니다.** 아래 PC 정보는 개발자가 알려준 참고 실행 환경이며, 일정 FPS를 보장하는 사양표는 아닙니다.

| 항목 | 참고 환경 / 요구 사항 |
| --- | --- |
| 플랫폼 | 현재 빌드 대상: Windows 64비트 |
| CPU | Intel Core i5 13세대 노트북 CPU — 정확한 모델 미확인 |
| RAM | 16GB |
| 그래픽 | 내장 그래픽 사용, 별도 외장 GPU 없음. 현재 빌드는 Direct3D 11 필요 |
| 카메라 | 일반 노트북 내장 웹캠 — 모델·해상도·FPS 미확인 |
| 화면 | 게임 출력 1920×1080 고정 |
| 주변 기기 | 키보드, 스피커 또는 이어폰, 전신을 촬영할 수 있는 공간 |
| 저장 공간 | 빌드 폴더 전체와 기록 파일을 저장할 여유 공간 필요. 용량은 포함 곡에 따라 달라짐 |

Windows의 현재 자세 인식 설정은 **CPU 추론**이며 기본 모델은 BlazePose Full입니다. 보조 카메라를 함께 사용하면 추가 추론 작업이 발생합니다. 정확한 최소 CPU·메모리, 60/120 FPS 달성 여부는 별도 측정이 필요합니다.

## 제작 목적·저작권 및 출처

본 프로젝트는 **졸업프로젝트의 개발·시연·평가 용도로 제작되었으며, 영리 목적으로 사용하지 않습니다.**

### 오픈소스 활용 및 직접 구현 범위

사람의 관절 위치를 추정하는 기능은 **MediaPipe Pose Landmarker**와 **MediaPipe Unity Plugin**을 활용합니다. 자세 추론 모델 자체를 직접 개발한 것은 아닙니다. 프로젝트에서는 이 추론 결과를 이용한 게임 진행, 기준 패턴과의 동작 비교·채점, 아바타 제어, 듀얼 카메라 자세 병합 및 기록 저장 기능을 구현했습니다.

오픈소스 구성 요소에는 각 구성 요소의 라이선스가 적용됩니다. 재배포 시 해당 라이선스와 저작권 고지, 서드파티 고지를 유지하고 각 라이선스 조건을 확인해야 합니다. 관련 문서는 위의 ‘사용 기술과 오픈소스’ 항목에 연결되어 있습니다.

### 외부 안무·영상·음원 등

일부 기준 안무 패턴은 **YouTube에 공개된 영상의 동작을 분석·추출하여 생성**했으며, 해당 이용에 대한 별도의 권리자 허락은 확보하지 않았습니다. 원본 영상별 URL, 안무가·제작자 등 상세 출처는 아직 정리되지 않았습니다.

원본 안무·영상·음원·이미지·아바타 등 외부 콘텐츠의 권리는 각 권리자에게 있습니다. 이러한 콘텐츠를 프로젝트의 독자 창작물로 주장하지 않으며, MediaPipe 등의 오픈소스 라이선스가 외부 콘텐츠의 이용 권한까지 부여하는 것은 아닙니다.

졸업프로젝트·비영리 목적이라는 설명이나 출처 표기만으로 이용 허락을 대신할 수는 없습니다. 본 안내는 외부 콘텐츠의 자유로운 재사용·재배포를 허용하는 문구가 아닙니다. 공개 배포 또는 다른 목적으로 활용하기 전에는 콘텐츠별 출처와 이용 조건을 확인하고, 필요한 허락을 받거나 이용 가능한 자료로 교체해야 합니다.

## 데이터와 저장 위치

- 곡 목록: `Assets/Data/SongData.csv`
- 동작 패턴: `Assets/Patterns`
- 음악 파일: `Assets/Musics/wav`
- 플레이 기록: `Application.persistentDataPath/records.json`
- 개발용 자세 비교 기록: `Application.persistentDataPath/TestingMode/pose_comparison_*.csv`
- 볼륨·아바타·FPS 설정: Unity `PlayerPrefs`

현재 Windows 제품 설정에서 기록 폴더는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\dance-game project`입니다. 회사명이나 제품명을 변경하면 저장 위치도 달라집니다.

## 실행 중 문제가 생기면

- **카메라가 나오지 않음:** Windows 카메라 권한, 웹캠 연결, 다른 앱의 카메라 사용 여부를 확인합니다. DroidCam은 필수가 아닙니다.
- **T포즈를 통과하지 못함:** 카메라에 전신과 양팔이 들어오는지, 조명이 충분한지 확인합니다. 개발 확인용으로는 안내 화면에서 `P`를 사용할 수 있습니다.
- **음악·패턴을 찾지 못함:** 빌드의 `*_Data/Patterns`, `*_Data/Musics/wav`가 존재하는지 확인하고, 누락됐다면 프로젝트에서 다시 빌드합니다.
